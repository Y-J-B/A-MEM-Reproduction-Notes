## 1. 数据集与规模

评测数据集为 **LoCoMo**（Long Conversation Memory），一个面向长对话记忆能力的基准。

| 项目 | 数值 |
|---|---|
| 样本数（对话数） | 10 |
| 会话数（session） | 272 |
| 对话轮数（turn） | 5882 |
| 平均轮数 / session | 21.6 |
| 问答总数 | **1986** |
| 参与评测的类别 | 1、2、3、4、5（全部纳入） |

**类别分布**

| 类别 | 含义 | 题量 | 占比 |
|---|---|---|---|
| 1 | 多跳（Multi-hop） | 282 | 14.2% |
| 2 | 时序（Temporal） | 321 | 16.2% |
| 3 | 开放域（Open-domain） | 96 | 4.8% |
| 4 | 单跳（Single-hop） | 841 | 42.3% |
| 5 | 对抗（Adversarial） | 446 | 22.5% |

数据不平衡需要说明：单跳题占四成以上，对抗题占两成，开放域不足 5%。因此**不能只看 overall 均值**，必须按类别分别报告。

## 2. 任务定义与判定口径

每条 QA 记录包含 `question`、`answer`、`evidence`、`category` 四个字段；对抗类额外含 `adversarial_answer`。

| 类别 | 任务定义 | 参考答案字段 | 判定方式 |
|---|---|---|---|
| 1 多跳 | 答案需跨越多条记忆组合推理 | `answer` | 文本相似度 |
| 2 时序 | 答案需结合会话发生的日期 | `answer` | 文本相似度，并要求给出近似日期 |
| 3 开放域 | 常识性或开放式回答 | `answer` | 文本相似度 |
| 4 单跳 | 单条记忆即可直接命中 | `answer` | 文本相似度 |
| 5 对抗 | 该信息在对话中**从未出现** | `adversarial_answer` | 干扰项二选一（见 §5.2） |

答案的选取逻辑实现在 `load_dataset.py:19-23`：类别 5 取 `adversarial_answer`，其余取 `answer`。

## 3. 评估指标

共 **14 项**，全部为**基于文本相似度的自动指标**，未使用 LLM 作为裁判（LLM-as-a-judge）。

### 3.1 主指标

报告正文建议只用以下两项做主对比，因为它们是与 Mem0 / A-Mem 等工作的公开表格口径对齐的常用指标：

- **F1**：分词后取词集合，计算精确率与召回率，再取调和平均（`utils.py:136-145`）。
- **BLEU-1**：`nltk.translate.bleu_score.sentence_bleu`，权重 `(1,0,0,0)`，平滑函数 `method1`（`utils.py:50-66`）。

### 3.2 辅助指标

| 指标 | 实现要点 | 代码位置 |
|---|---|---|
| exact_match | 小写化后**完整字符串相等**才计 1 | `utils.py:133` |
| ROUGE-1 / ROUGE-2 / ROUGE-L | `rouge_scorer.RougeScorer`，`use_stemmer=True`，取 F-measure | `utils.py:40-48` |
| BLEU-2 / 3 / 4 | 权重分别为 `(0.5,0.5,0,0)`、`(0.33,0.33,0.33,0)`、`(0.25×4)` | `utils.py:55` |
| BERTScore-Precision / Recall / F1 | `bert_score(lang='en')`，**逐条 QA 单独调用** | `utils.py:68-83` |
| METEOR | `nltk.translate.meteor_score`，按空格切词 | `utils.py:85-91` |
| SBERT 余弦相似度 | 用 `all-MiniLM-L6-v2` 编码后取余弦 | `utils.py:93-107` |

### 3.3 聚合方式

`aggregate_metrics`（`utils.py:167-211`）对每个指标分别在 `overall` 与 `category_1` … `category_5` 两个层级上统计：

- mean（均值）
- std（标准差，样本数 > 1 时计算）
- median（中位数）
- min / max
- count（样本数）

结果以 JSON 落盘，结构为 `aggregate_metrics.overall.*` 与 `aggregate_metrics.category_N.*`。

## 4. 评测协议

| 环节 | 设定 |
|---|---|
| 记忆构建 | 将对话中**每一个 turn** 逐条写入记忆系统，一 turn 一条记忆 |
| 记忆检索 | 问题先由 LLM 生成关键词，再做向量检索取 top-k，并拼接命中记忆的邻居节点 |
| 答题约束 | LLM **只能看到检索出的上下文**，不能访问原始对话 |
| 检索数量 k | 默认 10；原论文通过 k-sweep 为每个模型单独调优 |
| 答题温度 | 类别 5 为 0.5（`test_advanced_robust.py:346`），其余为 0.7 |
| 数据切分 | 无训练/测试划分，全量参与 |
| 缓存机制 | 记忆与检索器按 `{backend}_{model}` 命名落盘；更换 k 只重跑答题，不重建记忆 |

### 4.1 一个必须声明的性质

**答案所依据的证据 turn 本身就存在于记忆库中。** 因此本评测并非衡量模型的泛化或推理能力，而是衡量：

> 在给定完整历史记忆的前提下，系统能否正确检索并组织出回答所需的信息。

这一性质不构成数据泄漏（因为任务设定就是"全历史可用"），但若不在报告中说明，容易被误解为测试集泄漏。

### 4.2 记忆组织机制

评测的不仅是检索，还包括记忆的**动态组织质量**。系统采用 Zettelkasten 式笔记结构，每条记忆含 `content`、`keywords`、`tags`、`context`、`links` 五类属性；新增记忆时最多触发三次串行 LLM 调用：

1. 演化决策（是否需要强化或更新邻居）
2. 强化详情（补充连接与标签）
3. 更新邻居（修正邻居记忆的上下文与标签）

演化累计达 `evo_threshold = 100` 次时，重建一次向量索引（`memory_layer_robust.py:359`, `399-409`）。

## 5. 口径差异与局限性

以下三点直接影响结论的可比性，建议在报告中明确写出。

### 5.1 F1 采用集合去重

`utils.py:136-137` 使用 `set(simple_tokenize(...))`，即**同一词重复出现只计一次**。标准的 SQuAD 式 F1 使用 `Counter` 保留词频。

- 影响方向：答案较长、含重复词时，F1 会被系统性抬高。
- 影响程度：LoCoMo 答案多为短语，偏差有限，但**不宜与其他使用 Counter 的基线直接横向比较**。

### 5.2 对抗类（类别 5）判定被改写

原 LoCoMo 设定中，类别 5 考察模型**是否能够拒绝回答**未被提及的内容。

本仓库的实现（`test_advanced_robust.py:117-128`）改为：

1. 将正确干扰项与该句 `Not mentioned in the conversation` 随机打乱顺序；
2. 让模型在两者中二选一。

后果：模型仅靠随机猜测即可获得约 50% 的命中率。446 道对抗题占总题量 22.5%，其分数**不能解读为"拒绝能力"**。

### 5.3 只评估了答案质量，未评估检索质量

数据集中每条 QA 均带有 `evidence` 字段（形如 `D2:3`，即第 2 个会话第 3 轮），本可直接计算检索的 Recall@k 或证据命中率。

经全文检索确认，该字段**仅出现于 `load_dataset.py` 的数据结构定义中，评测代码从未调用**。因此当前体系无法回答"检索环节本身准不准"这一问题——端到端分数下降时，无法区分是检索错了还是生成错了。
